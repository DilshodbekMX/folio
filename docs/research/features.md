# AREA: Overleaf product feature inventory (user-facing spec for a single-machine self-hosted clone)

Overleaf's help moved from overleaf.com/learn/how-to, where those URLs now return 404, to a GitBook site at docs.overleaf.com. Adding `.md` to any page URL there returns Markdown, and https://docs.overleaf.com/llms.txt indexes every page. I downloaded all 117 user pages and also did a sparse clone of the AGPL overleaf/overleaf repo (HEAD e039ad2, 2026-09-17). From the clone I took the exact UI strings (locales/en.json resolved against each React component), menu structures, setting option lists, timing constants and the CLI commands the compile service runs. I read the code to learn how it works and did not copy it. The current Overleaf UI is the 2025+ "redesigned editor". It has a top bar with an Overleaf logo (back to the dashboard), File/Edit/Insert/View/Format/Help menus, the project-title dropdown, and on the right online-user avatars, an Editing/Reviewing/Viewing mode switch, History, Share and Layout. A vertical left rail holds File tree, Project search, Integrations, Review and Chat, with Help and Settings at the bottom. The page itself is a resizable split: the CodeMirror 6 editor, a divider carrying the SyncTeX arrows, and the pdf.js viewer. The Recompile split-button sits top-left of the PDF pane, with a "Logs and output files" badge button and a Download PDF button next to it.

The compile semantics are the most important thing to match exactly. The command is `latexmk -cd -jobname=output -auxdir=$DIR -outdir=$DIR -synctex=1 -interaction=batchmode -time`, then `-halt-on-error` (Stop on first error) or `-f` (Try to compile despite errors), then the engine flag: pdfLaTeX `-pdf`, LaTeX `-pdfdvi`, XeLaTeX `-xelatex`, LuaLaTeX `-lualatex`. Draft mode prepends `\PassOptionsToPackage{draft}{graphicx}\PassOptionsToPackage{draft}{graphics}` to the main file in the compile directory. Auto-compile waits for a 2500 ms pause in typing and fires at most 5000 ms after the first change. "Recompile from scratch" and "Clear cached files" delete the per-user compile directory. SyncTeX is plain `synctex view -i line:col:file -o output.pdf` and `synctex edit -o page:h:v:output.pdf`. Word count is `texcount -nocol -inc main.tex`. I checked the pulled texlive/texlive:latest-full image (TeX Live 2026, latexmk 4.88): it contains latexmk, synctex, texcount, chktex, lacheck, biber, bibtex, makeglossaries, makeindex, xelatex, lualatex and pdflatex, so all of these can run in the sandbox. The logs pane parses output.log and .blg files into Errors, Warnings and Info (bad boxes) tabs plus Raw logs, capped at 100 entries. Each entry has "Go to code location" and a human-readable hint. Below that are "Other logs and files" (.bbl, .gls and .ind first) and a red "Clear cached files" button.

Suggested priorities for a one-machine clone. Must: dashboard CRUD and zip upload, the file tree, a CM6 LaTeX editor with LaTeX-aware autocomplete, compile with the exact dropdown options, the pdf.js viewer, the logs pane, SyncTeX both ways, the outline, and basic history (versions, diff, restore, labels). Should: real-time collaboration with presence (Yjs), sharing roles and link tokens, word count, spell check, dark mode, Vim keybindings, project search, tags and archive, and comments. Nice: track changes (hard with Yjs), chat, symbol palette, figure and table modals, equation preview, detached PDF, templates, git remote access, offline editing. Skip: the Visual Editor (very large effort), AI, Dropbox and reference-manager integrations, journal submission, and docx/md conversion. For the user's paper (antiddos_v2.tex): it is 203 KB, uses `\documentclass{Definitions/mdpi}` and was compiled with XeLaTeX and \write18 enabled. It has 63 \bibitem entries and no .bib file, 39 \label entries and 14 inline TikZ/pgfplots pictures. The clone should therefore index \bibitem keys for \cite completion, which Overleaf does not do. It should also default this project to XeLaTeX, allow an optional sandboxed shell-escape, and use a long compile timeout of 180–240 s. Fast [draft] mode will not speed up this paper, because draft only affects graphicx and the figures are TikZ.

## [should] Archive / Trash / Delete semantics
Archive and Trash are per-user flags that only move the project in that user's list; collaborators are unaffected. Trashed projects are never deleted automatically. Permanent deletion happens only from Trash and only by the owner, and it removes the project for everyone with no undo. A collaborator can only Leave, from Trash. Restore returns the project to 'Your projects'. The clone can store `archivedBy[]` and `trashedBy[]` user-id arrays on the project.
Sources: https://docs.overleaf.com/managing-projects-and-files/archiving-deleting-and-leaving-projects/deleting-a-project

## [must] Text vs binary file classification
A file is an editable 'doc' if its extension (lower-cased) is in: tex, latex, sty, cls, bst, bib, bibtex, txt, tikz, mtx, rtex, md, asy, lbx, bbx, cbx, m, lco, dtx, ins, ist, def, clo, ldf, rmd, qmd, lua, py, gv, mf, yml, yaml, lhs, lean, lean4, hs, mk, xmpdata, cfg, rnw, ltx, inc. It is also a doc if its whole name is one of latexmkrc, .latexmkrc, makefile, gnumakefile. Everything else is a binary 'file'. Text over 2 MB (max_doc_length) becomes non-editable and read-only, and is excluded from search. Uploaded text is converted to UTF-8 and CRLF→LF. Overleaf rejects NUL and non-BMP characters because of its OT; Yjs does not have this restriction.
Sources: https://raw.githubusercontent.com/overleaf/overleaf/main/libraries/overleaf-editor-core/lib/text_file_defaults.js, https://docs.overleaf.com/troubleshooting-and-support/file-encodings-and-line-endings

## [must] Autocomplete: triggers and sources
Completion opens automatically on `\` and after `{` inside known argument types. Ctrl+Space (also on Mac) opens it explicitly; inside \cite{} it searches references. Up/Down select a candidate and Enter/Tab insert it. Sources: (1) about 100 top command snippets with tab-stops, e.g. \frac{$1}{$2} and \bibitem{$1}; (2) environments after \begin{, inserting the full block `\begin{env}\n\t$1\n\end{env}`; lists include `\item`, figure includes a centered includegraphics, array has a column spec; (3) user commands and environments defined anywhere in the project (\newcommand, \renewcommand, \DeclareMathOperator, \newenvironment); (4) \ref/\eqref/\autoref/\cref arguments complete labels from all project docs; (5) \cite/\citep/\citet… complete keys from all .bib files (parsed in a worker), headed 'FROM YOUR PROJECT'; (6) file paths: \input/\include/\subfile offer .tex/.txt with the .tex extension stripped, \includegraphics offers files matching /\.(eps|jpe?g|gif|png|tiff?|pdf|svg)$/i, \bibliography/\addbibresource offer .bib (stripped for \bibliography); (7) \usepackage package names, \documentclass classes, \bibliographystyle styles. The completion replaces the existing argument text up to `}`. There is a Settings toggle 'Auto-complete'. Clone improvements for this user: also index \bibitem{key} (the paper has 63 bibitems and no .bib) and offer .tikz for \input.
Sources: https://github.com/overleaf/overleaf/tree/main/services/web/frontend/js/features/source-editor/languages/latex/completions, https://docs.overleaf.com/citing-and-references/adding-citations-and-references/searching-for-references

## [must] Auto-close brackets and environments
The closeBrackets config covers ['$', '$$', '[', '{', '(']. LaTeX-specific rules: `\$` is not auto-closed, `\\$` gets a closing `$`, and `$` typed just before a `\command` is not auto-closed. The setting is 'Auto-close brackets — Automatically insert closing brackets and parentheses'. The matching \end{…} is added through the \begin completion snippet described above. Use @codemirror/autocomplete closeBrackets() with language data `closeBrackets: {brackets:[…]}` plus a custom input handler for the `$` rules.
Sources: https://github.com/overleaf/overleaf/blob/main/services/web/frontend/js/features/source-editor/languages/latex/close-bracket-config.ts

## [must] Code folding
Foldable regions: environment content (\begin…\end), a sectioning command through to the next heading of the same or higher level (the trailing newline is excluded), {…} groups, and custom comment markers where `% {` opens and `% }` closes, matched by the regexes /%\s*\{\s*/ and /%\s*\}\s*/ with nesting and a 6000-char forward search. ## [must] Compile backend: exact latexmk invocation
Overleaf's CLSI runs: `latexmk -cd -jobname=output -auxdir=$COMPILE_DIR -outdir=$COMPILE_DIR -synctex=1 -interaction=batchmode -time`, then `-halt-on-error` if stopOnFirstError else `-f`, then the engine flag {pdflatex:'-pdf', latex:'-pdfdvi', xelatex:'-xelatex', lualatex:'-lualatex'}, then `$COMPILE_DIR/<main>.tex`. Outputs are therefore always output.pdf, output.log, output.aux, output.synctex.gz, output.bbl and output.blg. Error states the UI handles: 'No PDF' (including when a project file is itself named output.pdf), and 'Conflicting Paths Found'. CE also ships a system latexmkrc with `$go_mode = 3;` so latexmk never skips a run in a persistent directory. The compile request body is {rootDoc_id, rootResourcePath, draft, check:'silent', incrementalCompilesEnabled, stopOnFirstError, editorId}, sent to POST /project/:id/compile with auto_compile=true on auto runs. Stop is POST /project/:id/compile/stop. Clear cache is DELETE /project/:id/output. Verified in texlive/texlive:latest-full: TeX Live 2026 with latexmk 4.88.

## [must] SyncTeX both directions

- AGPL: Overleaf's LaTeX grammar (npm lezer-latex 0.1.4 and codemirror-lang-latex 0.6.1), log parser, hint rules and React components are AGPL-3.0. Reimplement them. I copied only UI strings and generic TeX regex formats, not code.
- The symbol palette and full-project search are closed-source Overleaf modules missing from the CE repo. Symbol palette category names are unverified.
- The Visual Editor is a very large effort because it renders many constructs with CM6 decorations. Skip it in v1.
- Track changes assumes Overleaf's OT 'ranges' model. With Yjs it needs a custom design with relative positions and tombstones, and git or GitHub pushes can move or lose comment and track-change anchors, as they do on Overleaf.
- SyncTeX paths are absolute inside the compile container. Mount the compile directory at the same path for compile and synctex runs, or path lookups fail ('Couldn’t find the corresponding source file').
- TeX wraps log lines at 79 characters, which breaks error parsing. Set max_print_line/error_line/half_error_line through environment variables or rejoin wrapped lines.
- Shell escape: the user's build had \write18 enabled and Overleaf allows it. Full shell escape is only safe in a hardened container (no network, read-only root, dropped capabilities, resource limits) and should be a per-project toggle.
- Compile time: 14 TikZ/pgfplots pictures in one 200 KB file. A 10 s timeout like Overleaf's free plan would fail; use 180–240 s and consider externalization. Draft mode does not help with TikZ.
- Overleaf's 'compile the open file if it contains \documentclass' behaviour can surprise users with two root docs (antiddos_v2.tex and antiddos_v2_supplementary.tex). Show which file is being compiled.
- Help URLs under overleaf.com/learn/how-to now 404; any doc links must point to docs.overleaf.com or local help.
- Parallel compiles of one project corrupt aux files. Serialize with a per-project queue, and avoid stale-cache issues from compiles stopped halfway (offer Recompile from scratch).
- The texlive/texlive:latest-full image is about 5.6 GB, and pulling it concurrently with other runs is slow. Pin by digest (sha256:7334b00b… was pulled today) for reproducibility.
